# OpenHarness 开发规范

> 本目录是 OpenHarness 的开发规范与协作约定,适用于「人 + AI Agent」共同开发这一项目。
> 所有迭代必须遵循;规范本身也随项目演进,修改需在 commit 中说明。
> **各 Agent 工具的入口是仓库根目录 [AGENTS.md](../../AGENTS.md)**——硬规则摘要写在那里
> (每个 Agent 进仓库必读);本目录是细则与模板。

## 当前状态

- **当前版本:v0.3.0**(2026-08-15)——对话室、配置编辑与预设、活动流分页筛选、用量范围、完全自主模式
- **反馈轮次:第 1 轮已闭环**,见 [user-question.md](user-question.md)

## 开发闭环(一图流)

```
┌─────────────────────────────────────────────────────────────────┐
│  ① 用户反馈 → 记入 user-question.md(按轮次分节,标 ⏳ 待处理)     │
│  ② 版本更新启动:AI 通读全部未完成反馈                             │
│  ③ 逐项与用户确认决策点(选项式提问,推荐项放首位)                 │
│  ④ 生成 TODO.md(勾选式,来源/决策/验证项齐全)                     │
│  ⑤ 逐项实施,每项完成即验证(typecheck + build + 接口/UI 实测)     │
│  ⑥ 全部完成:更新 TODO.md(勾选)+ user-question.md(✅ 完成+v 版本)  │
│  ⑦ 更新 CHANGELOG.md / README 功能全景 → 按规范提交 commit        │
└─────────────────────────────────────────────────────────────────┘
```

## 速查:最不可妥协的 5 条

1. **未确认不动手**:反馈必须先与用户确认决策点,才能生成 TODO 并实施
2. **完成即验证**:每个 TODO 项必须过 typecheck + build + 接口或 UI 实测,禁止"看起来对了"
3. **密钥零泄漏**:任何接口不回显密钥明文,预设快照仅存本机
4. **用户配置不污染**:测试动真实配置文件必须先备份、验证后还原
5. **一个闭环一个 commit**:提交遵循 Conventional Commits 中文版
