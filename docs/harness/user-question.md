## 第 1 轮(2026-08-15)

> 状态:✅ 已完成(v0.3.0)

### 1. 对话式任务

问题现象:我发了任务之后只能等待任务结束了,并且无法有效干预。下一次再发送消息并没有上次任务的上下文了。

愿景:我希望各个Agent也可以保持会话的概念。也就是说不仅仅是只做对话传输,最好有个特定的对话入口,类似于Codex或者DeepSeek Harness那样的,能够在一个会话下持续进行问答,而不仅仅是展示一个实时活动流。并且我希望增加一个扩展功能,能够做到在一个会话中可以切换Agent。

> ✅ v0.3.0 交付:新增「对话室」Tab——会话列表(新建/删除)、聊天气泡、运行状态实时回填与打断;上下文经各工具原生 resume 续接(claude/codex/cursor),dsh headless 不支持 resume 则注入最近对话摘要兜底;同一会话内可切换 Agent(切换时注入最近 6 轮对话摘要);会话档案一键「对话室续聊」接续原生会话。

### 2. 配置速览

问题现象:这里只能看配置,无法直接修改配置。

愿景:可以修改配置、例如修改api key,baseUrl等。可以参考cc switch的功能。

> ✅ v0.3.0 交付:四工具配置逐字段编辑(api key / baseUrl / 模型 / 沙箱 / 审批策略等),写回原配置文件且其余内容字节级保留;密钥不回显(只提交新值,留空不改);cc switch 式预设:当前配置一键存为预设、一键应用/删除,快照仅存本机 ~/.openharness/presets.json。Cursor 为 OAuth 登录,页面给出说明。

### 3. 实时活动流

问题现象:这个页面只默认展示100条数据,并且数据多的时候要下滑页面,看消息不是很方便

愿景:支持分页,支持筛选不同的消息类似

> ✅ v0.3.0 交付:游标「加载更早」+ 每页 50/100/200 可选(加载旧页保持滚动位置);10 种事件类型多选筛选 + 关键词搜索 + 清除筛选;WS 事件携带入库 seq,与历史分页无缝去重。

### 4. 用量账本

问题现象:只能看14天的

愿景:增加更多选项

> ✅ v0.3.0 交付:统计范围档位 7/14/30/90 天/全部 + 自定义起止日期;全部聚合(总量/按工具/按模型/按天/按项目)随范围过滤,按天图标题联动。

## 第 2 轮(2026-08-15)

> 状态:✅ 已完成(v0.3.1);#4 复测、#7、#8 于 v0.3.2 闭环

### 1. 通知问题

问题现象:当任务完成时,会在右上角给我弹出通知,但是我看到是以脚本的形式呈现的,点击【展开】也是打开"脚本编辑器",正常情况下通知应该就是通知,以通知的形式呈现。

愿景:通知类似短信那种提醒就行,不要整成脚本编辑器。可以参考Codex完成任务后提醒。

> ✅ v0.3.1 交付:服务端通知改用 terminal-notifier(不再显示为"脚本编辑器",点击直达控制台),未安装时回退 osascript;二进制已装至 /opt/homebrew。

### 2. Agent权限问题

问题现象:我在对话室给小克安排了分析dema-ai-learn项目的任务,但是小克反馈由于权限原因导致任务失败了。

愿景:查看对话日志,分析原因并根治问题。同样的其余的几个Agent也要进行验证,保证都可以正常执行任务无需人工确认。

> ✅ v0.3.1 交付:claude headless 权限拦截不再"假完成",显性报错并提示勾选「完全自主」重试;发射台/对话室「完全自主」开关覆盖 claude/codex/cursor 原生参数;dsh/claude 已实跑验证全自主成功;codex 网络异常、cursor 未登录均显性报错(见下条)。

### 3. Cursor任务失败

问题现象:我在对话室给Cursor(光标侠)布置了一个任务,但是他没有反应,并且右上角有提醒我任务执行失败。

愿景:查看日志找到问题原因并修复。

> ✅ v0.3.1 交付:定位为 cursor-agent 未登录(OAuth,与 Cursor IDE 登录态不共享);失败时给出可操作提示。用户已执行 cursor-agent login,实测通过:直接任务与对话室任务均全自主完成(「收到」回复,exit 0),四工具全自主验证全部收齐。

### 4. 对话室的页面长度

问题现象:我尝试在对话室和各个Agent聊天,随着对话越来越长,会话室页面的长度也越来越长了,导致要看到最新的对话要不断的下滑,这点体验很不好。

愿景:希望参考其他Agent对话的方式(Codex/DeepSeek Harness),固定住下面的发送框,然后看到最新的几条对话,由于页面长度原因之前的会话要上滑看到。具体页面效果参考Codex/DeepSeek Harness。

> ✅ v0.3.1 交付:发送框固定底部;仅在"停在顶部/底部最新处"时自动跟随,读历史不被拽走;「↑ 最新」浮钮一键回顶;加载更早保持视口位置。
>
> 用户补充：问题没有修复，现象和之前一样还是会越聊越长需要下滑。
>
> ✅ v0.3.2 交付:复现定位真根因——页面 tab 容器缺 flex 高度约束,长对话把整页撑爆(页面总高 3000+px),发送框被推出版面。修复后实测:30+ 条消息的长对话页面零滚动、发送框固定、自动跟随最新。

### 5. 对话室的Agent切换

问题现象:我在对话里先和DeepSeek Harness对话,然后让它给我向Claude Code布置了一个任务,我在页面上确实看到了是小克在执行任务,但是当任务完成后我并没有收到任何的提醒和反馈。查看对话的日志分析。

愿景:希望上述情况在任务结束后能得到反馈。

> ✅ v0.3.1 交付:任务过程错误实时入对话气泡;任务收尾必有反馈(无助手输出时补系统气泡说明原因);task-start 携带 conversationId,Agent 间经本机 API 派活也会回流本对话(切换/续接时注入协作约定);修复任务气泡重复 bug。

### 6. 实时活动流顺序

问题现象：当前实时活动流是时间从前往后排的，但是实际用户只想看到最新的活动内容。

愿景：把时间由从前往后排改为最新的放到最前面。

> ✅ v0.3.1 交付:活动流改为最新在前(新事件置顶),自动跟随顶部;滚到下方读历史时出现「↑ 最新」浮钮;「加载更早」移至列表底部。

## 9. 任务完成了但是左侧状态还显示RUN

问题现象：见截图

看实时活动流可以看到DSH任务已经完成但是左侧特工状态仍显示RUN!

![image-20260815205657715](/Users/liuziying/Library/Application Support/typora-user-images/image-20260815205657715.png)

> ✅ v0.3.3 交付:根因——状态探测(pgrep)匹配"任意命令行里含单词 dsh"的进程,连脚本里 `"agent":"dsh"` 的字符串都会误判为干活中(字符串污染)。修复为"可执行位置"匹配(bin/dsh、dsh --profile 才计数)+ 任务收尾后 10s 清理残留进程组 + 状态延迟刷新收敛;claude 探测同步收紧。实测:任务完成瞬间起状态卡保持待命,不再误报 RUN。
