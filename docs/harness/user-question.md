## 第 1 轮(2026-08-15)

> 状态:✅ 已完成(v0.3.0)

### 1. 对话式任务

问题现象:我发了任务之后只能等待任务结束了,并且无法有效干预。下一次再发送消息并没有上次任务的上下文了。

愿景:我希望各个Agent也可以保持会话的概念。也就是说不仅仅是只做对话传输,最好有个特定的对话入口,类似于Codex或者DeepSeek Harness那样的,能够在一个会话下持续进行问答,而不仅仅是展示一个实时活动流。并且我希望增加一个扩展功能,能够做到在一个会话中可以切换Agent。

> ✅ v0.3.0 交付:新增「对话室」Tab——会话列表(新建/删除)、聊天气泡、运行状态实时回填与打断;上下文经各工具原生 resume 续接(claude/codex/cursor),dsh headless 不支持 resume 则注入最近对话摘要兜底;同一会话内可切换 Agent(切换时注入最近 6 轮对话摘要);会话档案一键「对话室续聊」接续原生会话。

### 2. 配置速览

问题现象:这里只能看配置,无法直接修改配置。

愿景:可以修改配置、例如修改api key,baseUrl等。可以参考cc switch的功能。

> ✅ v0.3.0 交付:四工具配置逐字段编辑(api key / baseUrl / 模型 / 沙箱 / 审批策略等),写回原配置文件且其余内容字节级保留;密钥不回显(只提交新值,留空不改);cc switch 式预设:当前配置一键存为预设、一键应用/删除,快照仅存本机 ~/.openharness/presets.json。Cursor 为 OAuth 登录,页面给出说明。

### 3. 实时活动流

问题现象:这个页面只默认展示100条数据,并且数据多的时候要下滑页面,看消息不是很方便

愿景:支持分页,支持筛选不同的消息类似

> ✅ v0.3.0 交付:游标「加载更早」+ 每页 50/100/200 可选(加载旧页保持滚动位置);10 种事件类型多选筛选 + 关键词搜索 + 清除筛选;WS 事件携带入库 seq,与历史分页无缝去重。

### 4. 用量账本

问题现象:只能看14天的

愿景:增加更多选项

> ✅ v0.3.0 交付:统计范围档位 7/14/30/90 天/全部 + 自定义起止日期;全部聚合(总量/按工具/按模型/按天/按项目)随范围过滤,按天图标题联动。

愿景:通知类似短信那种提醒就行,不要整成脚本编辑器。可以参考Codex完成任务后提醒。

> ✅ v0.3.1 交付:服务端通知改用 terminal-notifier(不再显示为"脚本编辑器",点击直达控制台),未安装时回退 osascript;二进制已装至 /opt/homebrew。

愿景:查看对话日志,分析原因并根治问题。同样的其余的几个Agent也要进行验证,保证都可以正常执行任务无需人工确认。

> ✅ v0.3.1 交付:claude headless 权限拦截不再"假完成",显性报错并提示勾选「完全自主」重试;发射台/对话室「完全自主」开关覆盖 claude/codex/cursor 原生参数;dsh/claude 已实跑验证全自主成功;codex 网络异常、cursor 未登录均显性报错(见下条)。

## 第 3 轮(2026-08-15)

> 状态:✅ 已完成(v0.3.4)

### 1. 手机窄屏下页面横向溢出

问题现象:在 390×844 的手机视口体验时,页面仍按桌面布局展示。对话记录与聊天区保持双栏横排,大部分聊天内容被裁切,必须横向滚动;顶部导航也被挤成狭窄竖列,文字逐字换行。

愿景:增加真正的响应式布局。窄屏下将导航改为可横滑但文字正常显示的标签栏,对话列表与聊天区改为单栏切换或抽屉,保证主要内容无需横向滚动即可阅读和操作。

> ✅ v0.3.4 交付:390px 窄屏适配——顶部导航横向滑动标签(文字不换行)、对话列表收进抽屉(☰ 对话)、活动流固定列窄屏收窄/隐藏、发送框与筛选行可换行;Chrome headless 390×844 实测无横向裁切。

### 2. 实时活动流重复展示同一条助手消息

问题现象:同一条 Codex 助手消息会连续出现两次,时间和内容完全相同。接口复核发现它们被保存为两个不同 seq 的事件,不是单纯的前端重复渲染;本轮多条助手消息均可稳定复现。

愿景:按来源事件 ID 或稳定指纹在入库前去重,并兼容清理已有重复记录,保证一条真实消息在活动流中只出现一次。

> ✅ v0.3.4 交付:入库按(agent+会话+类型+全文)指纹去重——发射路径与文件监听路径同一条消息只入库一次;一次性迁移清理存量重复 1415 条。实测消息类相邻重复为 0。

### 3. 内部注入上下文混入用户可见记录

问题现象:实时活动流和「发任务」抽屉的任务记录会把 `<recommended_plugins>`、系统提醒、运行时上下文、协作约定以及拼接后的 `[对话背景]` 当作普通用户消息完整展示。真实任务描述被这些内部内容淹没,也让用户误以为自己发送过这些文本。

愿景:展示层区分「用户原始输入」与「系统注入上下文」。默认只显示用户本轮真实消息;内部上下文如确有排障价值,放入明确标注的可折叠调试详情,并对可能包含的敏感信息做脱敏。

> ✅ v0.3.4 交付:①四工具解析器过滤 <recommended_plugins>/<system-reminder> 等系统注入,不再生成用户消息事件;②[对话背景]注入任务在展示层自动提取「[本轮消息]」之后的真实输入(活动流/会话标题/任务记录);③任务记录改用用户原始输入。dsh/claude 索引已重建。

### 4. 会话档案被 100 条硬截断且缺少翻页

问题现象:四个特工当前合计已有 177 个会话,但会话档案只请求并显示最新 100 条,页面没有「加载更多」或分页入口;搜索和特工筛选也只作用于这 100 条已加载数据,较早会话实际无法查找。

愿景:会话档案支持服务端分页或游标「加载更早」,搜索与特工筛选覆盖全部会话,并显示「已加载数 / 总数」让用户知道档案是否完整。

> ✅ v0.3.4 交付:会话档案服务端分页(游标「加载更早」),头部显示「已加载 X / 共 Y」;搜索与特工筛选下推服务端,覆盖全部会话。

### 5. 空会话与测试数据挤占会话档案

问题现象:会话档案顶部存在大量标题仅为会话 ID、项目为「—」、消息数为 0 的记录,有效会话很快被挤到下面;同时还残留明显的测试记录,例如 `01a88888-aaaa-7bbb-cccc-dddddddddddd` 和「watcher测试回复2」,其时间还显示为未来的 08/16 05:12。

愿景:默认隐藏或单独归档 0 消息会话,提供「包含空会话」筛选;测试产生的数据验证后自动清理,异常未来时间应标记或纠正,避免污染真实档案排序。

> ✅ v0.3.4 交付:默认隐藏 0 消息空会话并提供「含空会话」开关;清理残留测试文件与记录(01a88888 等);修复 claude/dsh「已消费文件重启后汇总清零」的历史 bug 并重建索引,档案总数从虚高的 177 收敛为真实数据。

### 6. 配置页仍展示密钥首尾字符

问题现象:配置页文案写着「页面不回显」,但认证令牌和 API Key 输入框的 placeholder 仍展示脱敏后的首尾字符(例如前 4 位和后 4 位)。在截图、录屏或旁观场景下仍会泄露可用于识别密钥的信息,也与页面承诺不一致。

愿景:密钥字段只显示「已设置」与「留空不改」,不向前端返回任何密钥片段;如需帮助用户辨认不同凭据,使用用户自定义别名或不可逆指纹的极短标识。

> ✅ v0.3.4 交付:密钥字段不再向页面返回任何片段——输入框只显示「已设置/留空不改」,只读摘要与预设列表一律用占位符(••••••••)展示,首尾字符不再出现。

### 7. 用量账本的按天日期轴不连续

问题现象:选择「近 14 天」时,按天图只展示 08-03、08-12、08-13、08-14、08-15 等少量日期,中间日期直接消失;自定义 30 天范围也有同样现象。横向间距却保持均匀,容易把相隔多天的数据误读为连续日期。

愿景:按所选范围补齐每天的零值数据,保持真实连续日期轴;范围较长时可抽稀日期标签,但数据柱和悬浮提示仍应对应完整日期。

> ✅ v0.3.4 交付:按天图对所选范围逐日补零,日期轴连续(近 14 天实测 15 个连续日期点);超过 45 天自动抽稀标签,数据柱与悬浮提示仍逐日完整。
